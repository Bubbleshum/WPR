short summary that goes on the release page is [`0.2.04.md`](0.2.04.md) beside this file.

### Windows Phone 8 native games

Windows Phone 8 allowed two kinds of native game, and WPR now runs both:

- **"Modern Native" games**: an ARMv7 Thumb-2 executable that talks to WinRT and Direct3D 11
  directly. All seven Angry Birds titles are this kind.
- **Direct3D/XAML games**: the XAP says "Silverlight", but the managed page only hosts a native
  ARM WinRT component that does all the work. Amazing Alex and Modern Combat 4 are this kind, and
  so are 43 titles in the test library, including GTA San Andreas, Asphalt and Rayman.

**How they run.** The ARM code runs on [dynarmic](https://github.com/merryhime/dynarmic), a JIT that
translates ARM into x86-64 or arm64 as it goes, through a small native shim (`wprcpu.dll` on
Windows, `libwprcpu.so` on Android). Around it, WPR implements the parts of Windows Phone 8 these
games import: the C and C++ runtimes, Win32 file I/O, threads, mutexes and condition variables,
WinRT activation and events, the Concurrency runtime, XAudio2, Direct3D 11 and Xbox Live. The
game is then shown as an ordinary XNA game, so it uses the same window, graphics drivers and input
as every other title.

Guest threads are cooperative: a game thread runs until it blocks (a mutex, a condition variable,
a sleep, a join), and the frame loop gives every other thread a turn each frame. A thread ended by
an uncaught exception releases the mutexes it held, as unwinding would have; Angry Birds Rio's
network thread dies holding one.

**WP8 ARM code passes floats in VFP registers** (hard-float). That was the cause of a long-standing
"level won't load" bug in Angry Birds Rio: the maths library (`sinf`, `pow`, `floorf` and friends)
read its arguments from the wrong registers.

**Direct3D/XAML games need their page described.** The managed C# page that hosts the native
component isn't run: there's no Silverlight runtime for it to run on. Instead WPR plays the page's
part from a short description (which properties it sets, which events it subscribes, what it does
on Back) written from the game's decompiled page code. Amazing Alex and Modern Combat 4 have one.
Other games of this kind install, then refuse to launch with a message saying so.

**Installing.** A WP8 "Silverlight" XAP that registers a native ARM component (and isn't Unity) now
installs as a native game. If the XAP carries several native components, WPR picks the one that
imports `d3d11.dll`.

**Android needs a 64-bit (arm64) phone.** The JIT is built for arm64 and x86-64 only; there is no
32-bit ARM build. Every phone used for testing (and the emulator) is 64-bit.

### Speed

- **The JIT's fast memory path covers read-write memory**, not just read-write-execute. Every heap
  and stack access used to go through a callback; on a Galaxy S24 that was about 43% of the game
  thread. Angry Birds Space went from 20–25 fps in a level to a steady 60.
- **The JIT's code cache is 128 MB**, the most dynarmic's arm64 backend allows. At 256 MB every WP8
  game crashed on start-up on a real phone, though not on the x86-64 emulator.
- **Imports are bound to their handlers on first call**, instead of being looked up by name on every
  call. Modern Combat 4's loading screens make about 1.7 million such calls a second.
- **The unpacked game is indexed once**, instead of searching the folder segment by segment on every
  file open (about 18% of the game thread while loading on a PC).
- **Freeing memory no longer gets slower the longer a game runs**: the double-free check was a linear
  scan of every block freed at that size.

On a PC, Modern Combat 4's mission loading went from 1–3 fps to 10–13 fps. On a Galaxy S24 it's still
1–2 fps; see known issues.

### Modern Combat 4 and the 3D renderer

Angry Birds and Amazing Alex draw flat sprites, and WPR draws those through a 2D path that turns each
frame's Direct3D calls into a list of textured rectangles. Modern Combat 4 is a 3D game with its own
shaders, which that path can't show.

**Every feature-level 9 shader carries its Direct3D 9 twin.** Direct3D 11 shaders for phones include
an "Aon9" chunk: the equivalent Direct3D 9 program plus maps of where its constants and samplers
live. WPR extracts it, wraps it in a minimal effect, and hands it to MojoShader, the same shader
compiler XNA games already use, so no shader translator was needed. All 213 of Modern Combat 4's
shaders have one.

**Frames are recorded, then replayed on the GPU.** WPR records the game's shaders, state, constant
buffers, textures, render targets, clears and draws in order, copying the data each draw used at the
moment it was issued, then replays the frame through FNA on whichever driver you're on: Direct3D 11
on Windows, Vulkan or OpenGL ES on Android. Static meshes are uploaded once and reused; geometry
rewritten every frame goes through a shared buffer.

Only Modern Combat 4 uses this path for now. It's switched on per game after testing; Angry Birds and
Amazing Alex already look right in 2D and stay there.

Fixes the game needed along the way, all general:

- **Depth clears now clear the depth buffer the next draw actually uses.** In Direct3D 11 a depth
  view is its own texture; FNA ties depth to the render target. The whole world failed the depth test.
- **Vertex streams with a stride of 0** (every vertex reads the same value) are supported. The game
  passes each draw's colour that way, and about 6% of draws were dropped without it.
- **`atoi` stops at the first non-digit.** It read the whole string, so `"80.tga"` was 0, every
  animation frame lasted 0 ms, and the game divided by their total.
- **`_aligned_malloc` and its family exist.** Without them 83 objects were built at address 0.
- Win32 file reads and writes (including overlapped), seeking and file sizes on `CreateFile2`
  handles; Win32 mutexes and semaphores; `_Thrd_create`; a dozen string and locale functions.
- The XAML page's static events, singleton components and follow-up calls (for example "the movie
  finished"), and its Back handler.
- Xbox Marketplace answers "no offers, nothing owned"; purchases buy nothing.

The Windows `wprcpu.dll` was rebuilt in the middle of this: the committed one predated the
read-write fast path, so on a PC every memory access still went through a callback. That alone was
the difference between 28 and 60 fps.

### Sound

XAudio2 used to throw every buffer away, so WP8 games were silent. Source voices now play: PCM of any
width, IEEE float and MS ADPCM are converted to 16-bit, loops and play ranges are honoured, volumes
follow the submix and mastering voices, and the frequency ratio becomes pitch. Voice and engine
callbacks (`OnBufferEnd` and the rest) fire on the game's own thread once a frame, and a buffer only
counts as finished once it has been heard.

**On Windows** each voice is an FAudio stream driven directly from the game's thread, under the same
lock XNA's own update takes. The first version passed every call through the XNA thread and took
three or four frames to refill a voice, which ran dry every cycle.

**On Android** each voice is its own `AudioTrack` instead. FAudio's output on Android pulls audio in
large bursts, and a game keeping only 50 ms queued (Modern Combat 4 keeps two 25 ms buffers) ran dry
several times a second. Three details mattered:

- **A streaming `AudioTrack` won't start until its buffer is full**, and these games never queue that
  much. The track now starts after 10 ms (Android 12 and later), or its buffer is primed with silence
  (earlier versions).
- **Voices are resampled to the phone's native rate.** Modern Combat 4 mixes at 32 kHz; the S24 runs
  at 48 kHz. Android refuses a 32 kHz track its low-latency path and resamples it itself, which
  sounded dull and still gapped about once a second. WPR's own resampler (windowed sinc, 16 taps)
  converts it first, and the track gets the fast path. Pitch changes go through the resampler too.
- **No extra latency was added.** Queuing more audio ahead was tried and made every click and
  gunshot audibly late.

On a Galaxy S24 the track now runs on Android's fast mixer, and Modern Combat 4's intro plays without
underruns. Sounds pause when the game goes to the background.

### Touch and the Back button

- **Every finger reaches the game**, each as its own pointer, and every touch event in a frame is
  delivered in that frame. With one event a frame, two moving thumbs fell further behind every frame.
- **A tap whose "pressed" sample was missed still counts.** A finger first seen already moving now
  starts a touch.
- **Back reaches WP8 games**: the hardware key on Android, the Back key binding on Windows. A press
  the game doesn't handle closes it, as on the phone. In Angry Birds Rio, Back on the menu opens the
  quit dialog and in a level opens pause; in Amazing Alex it skips the comic and opens pause.

### Xbox Live, served by WPR

- **Achievements** unlock through the same path as WP7 games: a toast, the trophy pages, and the
  upload to WPR Hub when you're signed in. A game's achievement list reports what you've earned.
- **WP8 games unlock by number, so their catalogues are now keyed by Xbox achievement id.** Before
  this, 66 bundled catalogues were keyed by name and could never unlock anything in a WP8 native
  game. They're converted, and WPR updates the keys of earned achievements at start-up, so nothing
  is lost and nothing needs reinstalling.
- **Ten games that had no achievements now do**, with names, scores and icons read from the Xbox
  data inside the game: Halo: Spartan Assault, Halo: Spartan Strike, Terraria, Lines The Game,
  MONOPOLY Millionaire, Babel Rising 3D, FIFA 13, Briquid Mini, Mass Effect Infiltrator and Bubble
  Guriko. The seven Angry Birds catalogues have their icons.
- **Leaderboards** post to and read from WPR Hub.

### Angry Birds Stella

Stella sat on its "connecting" screen for ever. Four bugs were in the way, all general:

- WPR answered "class not registered" for the phone's HTTP client, which no phone does. Requests now
  fail as they would with no signal, after a second (failing at once let the game retry about 170
  times a second).
- The task library thought every thread was the UI thread, so waiting on a task threw.
- Unwinding through some functions read the return address from the wrong slot, so C++ exceptions
  passing through them were reported uncaught. This may also be an Angry Birds Space crash seen on
  2026-10-06.
- `throw;` (rethrow) lost the exception being rethrown, so only `catch (...)` could catch it.

With those fixed, Stella behaves like a phone with no signal: it retries its Rovio sign-in once a
second and handles every failure. It still can't get past the screen; see known issues.

### Windows: fullscreen keeps its shape

A game running fullscreen on Windows is fitted to the largest rectangle of its own aspect ratio,
centred, with black bars, instead of being stretched to the monitor. Mouse input is mapped through
the bars. The choice is remembered and is on the settings page. Windowed play and phones are
unchanged.

### Android: an unsupported game no longer condemns Vulkan

Found on a Galaxy S24 right after 0.2.03. WPR remembers when a launch on Vulkan never drew a frame,
and since 0.2.03 that memory sticks, so the phone stays on OpenGL. But the mark was put down before
WPR checked whether it could run the game at all. Tapping a game WPR refuses (a Silverlight app, for
example) draws no frame, so one tap moved the phone to OpenGL for every game afterwards. The mark now
goes down when the graphics driver is first touched, which an unsupported game never reaches.

If your phone moved to OpenGL this way, open settings → graphics and pick Vulkan.

### What was tested

- **Windows (Direct3D 11):** all seven Angry Birds titles, Amazing Alex and Modern Combat 4 at 60 fps
  with sound. Modern Combat 4's first-mission intro also checked on Vulkan and OpenGL.
- **Galaxy S24 (Adreno 750):** Angry Birds Space and Modern Combat 4 on Vulkan, Modern Combat 4 also
  on OpenGL ES, including two-thumb play.
- **Android emulator:** Angry Birds Rio played into a level; Modern Combat 4 reaches its title screen
  on OpenGL ES.

Not every Angry Birds title has been played on a phone; they share one engine and one code path, so
they're expected to behave like Space. Nothing has been run on a Mali phone.

### Known issues

- **Loading is slow on phones.** Modern Combat 4's loading screens run at 1–2 fps on a Galaxy S24
  and its sound drops out meanwhile, because loading keeps the game's main thread busy and the JIT is
  the remaining cost there. Missions run at 60 fps once loaded.
- **Sound in WP8 games can still drop out now and then on Android**, less often than before.
- **Angry Birds Stella can't get past "connecting".** It needs Rovio's sign-in server to answer.
  WPR Hub standing in for it is planned.
- **Most Direct3D/XAML WP8 games don't start yet.** Each needs its page described; only Amazing Alex
  and Modern Combat 4 have one so far.
- **Modern Combat 4's briefing movies are skipped**, as there's no video player for WP8 native games.
- **On Windows, Modern Combat 4 under a forced OpenGL ES context** (a developer test mode, not
  something players reach) draws only sea and sky. The phone draws it correctly on OpenGL ES, so this
  looks specific to that desktop mode, but it hasn't been confirmed on the emulator yet.

> **Upgrading is normal.** Install the new APK over the top on Android, or run the installer on
> Windows. Your games, saves and sign-in stay put. Nothing needs repatching or reinstalling. A WP8
> game you installed before this release (when it couldn't run) needs reinstalling from its XAP.
