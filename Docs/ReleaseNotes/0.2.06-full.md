# WPR 0.2.06: full release notes

The long version: what each change actually is, how it behaves, and what's still missing. The
short summary that goes on the release page is [`0.2.06.md`](0.2.06.md) beside this file.

---

**Halo: Spartan Assault, Assassin's Creed Pirates, MONOPOLY Millionaire and 2020: My Country join the Windows Phone 8 games that run, Silverlight games come to Android, and Windows Phone 7 movies finally play.**

| 🎩 | **MONOPOLY Millionaire** runs, with its music at the right speed. The all-white screen on Android is fixed |

### The Windows Phone 8 runtime

0.2.04 ran the ARM code of a handful of WP8 titles, with the parts of Windows Phone 8 they used
written one game at a time. This release turns that into one runtime for every title.

- **Nothing unimplemented stops a game.** An import or WinRT member WPR has no handler for is
  answered with a default (0, or a value shaped by its real signature from Windows' metadata) and
  recorded, and the game carries on. A guest that stops on its own is reported to WPR Hub with its
  reason and a post-mortem. `WPR_WP8_TRAP_IMPORTS=1` restores stop-at-first for diagnosis.
- **The census is at zero.** Over the 102 titles with ARM code in the test library there are 1,208
  distinct system imports, and every one now has a handler (`Plans/WP8-API-CENSUS.md`). That took
  the C runtime (strings, printf/scanf, floating point, memory, time, stdio, low-level I/O, threads),
  the C++ library (exceptions, containers, `exception_ptr`, iostreams, locales and facets), ConcRT/PPL,
  vccorlib (Platform exceptions in vccorlib's own layout, boxing, activation, HSTRING), Win32 (files,
  synchronisation, locale, `VirtualQuery`, `RaiseException`, ETW), WinRT system classes (package,
  storage, streams, settings, app model) and Winsock, which now opens real sockets.
- **A module loader.** DLLs a game ships beside its executable are mapped, relocated, bound and
  initialised (`DllMain`), with per-thread TEBs, static TLS, forwarders and unload. C++ exceptions
  cross module boundaries. Assassin's Creed Pirates loads 40 such modules.
- **One render path.** Every title now replays its Direct3D 11 frames on the GPU with its own
  shaders; the per-title allow-list is gone. Frames are replayed exactly once and in order, mip
  levels no longer land on level 0, vertex inputs follow the shader's own declarations, scissor
  rectangles are honoured (Angry Birds Stella's achievement list no longer scrolls over its title),
  and BC textures reach the GPU as blocks.
- **A WXGA phone.** WP8 games are told they are on a 768x1280 panel at scale 160 (a Lumia 920);
  `CoreWindow.Bounds` and touch stay in 480x800 logical units as on WP8, and a game that sizes its
  swap chain from them gets the size it asked for. `WPR_WP8_RESOLUTION=wvga|wxga|720p` changes it.
- **Lifecycle.** Every title gets `Activated`, `VisibilityChanged`, `Suspending` and `Resuming` when
  WPR loses and regains focus. A Direct3D/XAML title also gets what its managed page and drawing
  grid did on WP8: its shell's deactivate/activate calls, and `Disconnect`/`Connect` of its content
  provider. While disconnected it draws nothing and takes no input. Measured on Windows: Amazing
  Alex, Modern Combat 4 and AC Pirates all disconnect, reconnect and draw at 60 fps, and Alex's Play
  button works afterwards.
- **Key repeat.** A held key repeats `KeyDown` at the Windows keyboard rate (else 500 ms / 33 ms).
- **Sound.** WP8 voices now go through the same audio registry as everything else. On Android they
  stream onto `AudioTrack` with WPR's own resampler at the device's native rate (measured on a Galaxy
  S24: no more underruns than before); on Windows they stay on FAudio. MONOPOLY Millionaire's music
  played at 70% of real time because its two audio threads managed one round trip per frame; the
  scheduler now lets them finish within a frame (measured: 38% → 100% of real time).
- **Compressed audio and movies through the platform.** The media engine decodes MP3 and similar
  sources through the platform's decoder (FFmpeg on Windows, MediaExtractor + MediaCodec on Android),
  and plays movies (ASF/WMV and MP4) into the game's own texture. Media Foundation byte streams and
  property stores are implemented.
- **Quitting with `exit(0)` is not a crash.** Rovio's games quit that way from their main menu, and
  were being reported to WPR Hub, and shown the new error screen, as failures. `exit(0)`, `_exit(0)`
  and `CoreApplication.Exit()` now end the game normally.
- **No allocation per guest call.** See Assassin's Creed Pirates below.

### Titles

**Halo: Spartan Assault** used to stop at frame 0 (`CPU exception 12 at 0xFFFFFFFE`). It now plays
its four logo movies and the intro cutscene, saves, and goes main menu → operation movie →
operation and mission select → armory → mission. Eight runtime defects were in the way at first,
each hiding the next: a 64 KB cap on C++ static initialiser tables (Halo has 37,303 initialisers),
`OMGetRenderTargets` answering nothing, a missing `ID3D10Multithread`, stack checks that only knew
the main thread, the media engine refusing every movie, `GetDesc` answering the back buffer's
description for every texture, copies between resources doing nothing (all-black menus), and
transacted file writes leaving a 0-byte save that then failed every read. Then, from a crash at
mission start reported on a Galaxy S24: a missing `ID3DUserDefinedAnnotation` (the light pass
called through null), by-value C++ catches getting the exception's address instead of its value
(the "unexpected save data error"), exceptions leaving a ConcRT task ending the worker thread
(a first run stuck on CONNECTING), and only the last subscriber of each touch event hearing it.

| cell | phone save → mission → two thumbs → play | first run, no save |
| --- | --- | --- |
| Windows, Direct3D 11 | ✅ gameplay | ✅ main menu, save written |
| Windows, Vulkan | ✅ gameplay | not run |
| Windows, OpenGL ES 3.0 without DXT | ✅ gameplay | not run |
| Android emulator, Vulkan and OpenGL ES 3.1 | ✅ logo movies, intro cutscene, menus (after a re-patch) | |
| Galaxy S24 | not run after the fix | |

On Android Halo used to sit on its first logo: WP8 packages never got the movie sidecars Android
needs (MediaCodec has no WMV), and NVorbis hangs reading past the end of an Ogg stream whose first
granule is not 0, which ffmpeg's encoder writes. Both fixed; the second also affected WP7 movies.

**Assassin's Creed Pirates** (Ubisoft's Spark2 engine) needed its page built with the package's own
WinRT components activated from the manifest (`LuaMobileSDKBridge`), `AudioRoutingManager`, real
handles for CRT descriptors (its SQLite saves), and several GPU replay fixes (skinned shaders, which
killed the process loading Devil's Rock; mip levels; frame replay). It was then reported as "really
slow on my phone": ~370 garbage collections a second on the menu and memory climbing to 2.9 GB. The
runtime allocated an array on every guest memory access, resolved indices per draw into new arrays,
and kept two unbounded lists. Measured on Windows, which reproduced it exactly: private bytes after
130 s 7.0 GB → 2.0 GB and flat, allocation in play ~190 MB/s → ~20 MB/s. Achievements and the
leaderboard menu reach WPR Hub.

**MONOPOLY Millionaire** died before its first frame (a page-crossing memory access aborted the ARM
JIT; the native `wprcpu` was rebuilt for all platforms), then called through a camera property WPR
left null. On Vulkan and OpenGL every sprite was white (a NaN shader constant compared differently
from Direct3D) and every label vanished (MojoShader's SPIR-V places vertex inputs by register number,
FNA3D's Vulkan driver binds by position). Both are fixed in the bytecode WPR hands over, so every
driver gets the same shader. Verified on Windows: Vulkan and OpenGL now match Direct3D 11.
Starting a Pass 'n Play game unlocked an achievement live on WPR Hub.

**2020: My Country** (SDL for WinRT) presented no frames: SDL sleeps by waiting on its own thread
handle, which WPR answered as already signalled, so the worker thread it had just started never ran.
That is now a sleep. Then taps on its buttons and map did nothing, because the page arguments the
engine scales touch by were guessed by name (`SetViewDimensions(0,0,0,0)`); they are now computed by
running the managed page's IL. Light seams round every map tile came from an atlas texture created
without data on a reused heap block; such resources are now zeroed, as Direct3D does. Verified on
Windows (Direct3D 11, Vulkan, OpenGL ES): tutorial → Build → place a building, no seams.

**Angry Birds**: Rio's frame-53 fault (an HTTP request releasing its callback too early), Alex's
profile folder, and Seasons, Star Wars and Star Wars II's leaderboard menus, which stopped on "Sorry,
we're not sure what happened" because their boards are defined on Xbox Live's servers rather than in
the game. WPR now carries those board lists (21, 9 and 17 boards). Verified on Windows against a
test hub: Seasons posts a won level and reads it back beside another player.

### WP8 achievements and leaderboards

Every in-scope WP8 title calls Xbox Live from native code, so there is one path: the WinRT
`Microsoft.Xbox` surface → WPR's Xbox Live host → the same achievement store, toast and upload as
WP7 games, and WPR Hub leaderboards. Boards come from the title's Xbox SPA (id, name, aggregation);
Sum boards are totalled locally because the hub keeps a player's best; Min boards are lower-wins;
zero scores are not sent. Verified live: Angry Birds Classic (a score posted and read back beside
another player), MONOPOLY (an unlock with its toast, uploaded with playtime), AC Pirates (sign-in,
achievements, a leaderboard read).

### Every game is attempted

WPR now refuses a game only when there is genuinely nothing to run.

- **No or broken manifest**: `WMAppManifest.xml`/`AppManifest.xaml` are completed or synthesised
  from the package (an XNA `Game`, a Silverlight `Application`, an ARM executable), with identity
  from the manifest, the entry assembly or the file. The synthesised files are written to the
  install folder, and WPR Hub is told.
- **Unknown runtime types** are guessed (an `.exe` default task is native, anything else Silverlight).
  A failed patch or audio conversion no longer fails the install.
- **Direct3D/XAML titles with no hand-written page** have their page inferred from the managed
  shell's IL: which component, how it is created, which calls happen at launch, load, orientation
  change, deactivate, activate and Back, and with what arguments. With the hand-written descriptions
  ignored, Amazing Alex, Modern Combat 4 and AC Pirates reach the same screens on inferred ones. All
  32 background-grid titles in the library now get as far as connecting their renderer.
- **`DrawingSurface` titles** (Fruit Ninja 2013, Jetpack Joyride) are hosted and draw frames.
- **Classification**: WP8 managed games that ship a native helper library (SharpDX, Lumia Imaging)
  were treated as native games and stopped at frame 0; they now run as Silverlight. Components whose
  `.winmd` is named after their namespace are found again. Titles named `@AppResLib.dll,-100` get
  their real name from the package's resource DLL.
- **DRM-wrapped Marketplace downloads** are detected and refused as "not decrypted" instead of
  "unexpected error".

Survey of the 290 distinct packages in the library: no appx/appxbundle; every `.xap` reaches a host.

### The error screen

A WP8 guest that stopped used to close the window or leave it black; an XNA or Silverlight game
whose every frame threw and drew nothing ran on black for ever. Both now show the game's name,
what went wrong, where, and whether WPR Hub was told, until you press Back (Esc on Windows). The
frame watch only trips after 60 consecutive frames and 2 seconds in which every frame threw *and*
drew nothing, so games that throw but still draw (Feed Me Oil, Chickens Can't Fly, Brain Challenge)
never see it. Verified on Windows across all four graphics drivers; not yet seen on Android with a
real failing game.

### Reports to WPR Hub

With server logging on (the default), a run now reports what it carried on past, not only crashes:
missing types and members, exceptions thrown out of frames, unsupported rasteriser features, and
refusals and install problems. Each distinct problem is its own crash report shaped so the hub groups
it across games ("RichTextBox is missing" in ten games is one group), at most 10 per run, and each
(title, problem, WPR version) is sent once. A native crash no longer loses the list: problems are
written to disk as they happen and sent by the next start. With server logging off, nothing is sent.

**For hub operators**: these reports need the WPR Hub branch `compat-reports-as-crashes` deployed.
On an older hub they still group, but count as crashes on the compatibility pages.

### Silverlight: one player on both platforms

Silverlight games used to run inside the Windows launcher's own window (Avalonia), which had no
Android counterpart. Every Silverlight title now runs in WPR's game host with the CPU rasteriser, on
both platforms; the Avalonia host and the Direct3D 11 Silverlight renderer are gone. On Windows they
open in a game window with no phone frame; Back is Esc.

What pure Silverlight titles needed, all general: files in the package found by `GetResourceStream`
(Flowerz's strings and images; it also fixed Big Buck Hunter Pro's black start page), `Loaded` raised
on the root and on elements added later, re-layout when a page invalidates itself, `Frame.Content`
swaps, `FrameworkDispatcher.Update` from a background thread no longer racing taps, Panorama and Pivot
swipes, `ListBox` selection on tap, mouse event types. The rasteriser gained real shapes (ellipses,
lines, polylines, polygons and paths with arcs, dashes, caps and joins, both fill rules), WP7 control
chrome (buttons and the other stock controls, including games' own subclasses of them) and open popups, which are
also hit-tested.

| title | Windows (all four drivers) | Android emulator (Vulkan and OpenGL ES) |
| --- | --- | --- |
| Flowerz | menus, board, pieces placed | same |
| Minesweeper (WP7) | dashboard, panorama, classic | same |

`MessageBox.Show` used to throw on every call. It now shows a real dialog and blocks the game until
it is answered: "ok"/"cancel" as on WP7, Back or closing it counting as Cancel. Verified on Windows
with Big Buck Hunter Pro's "delete your progress?" question; the Android dialog was built but not
clicked through.

These were patcher changes (versions 41 and 42). Installed games are repatched automatically the
next time they're started.

### Songs and movies

**Songs** stream on FAudio again, on both platforms. FAudio's own song player decoded one second at a
time with one buffer queued, which clicked once a second on phones; WPR's player keeps six 125 ms
buffers queued from a decode thread. Measured on the emulator: no underruns over a minute of Mirror's
Edge. **On Android, FAudio now has its own AAudio output** (Android 8.1 and up) instead of SDL's,
which mixed about 130 ms ahead of the speaker and allowed only one output, so music and effects each
get a low-latency stream.

**WP7 movies**: 87 `.wmv` and 41 `.mp4` across about 55 titles used to be skipped as if finished.
`MediaPlayerLauncher` now takes the screen as WP7's player did (Back leaves, a tap skips where the
game allows it), and `MediaElement` draws inside Silverlight pages. Windows decodes with ffmpeg;
Android with MediaCodec, from MP4/Ogg copies written at install or re-patch. Verified: NFS Undercover
and Sid Meier's Pirates! on Windows, Cut the Rope's intro on the Android emulator.

### Known issues

- **Halo**: in play, some crates, Covenant units and parts of the weapon panel draw as solid black
  shapes on every driver. A mission needs two fingers at once, which a mouse can't give, so on
  Windows a mission can't start without a touchscreen. Not yet run on a phone after the mission fix.
- **Assassin's Creed Pirates**: about 30 seconds of freeze after Play. It is CPU, not memory: ~40%
  of it is guest memory copies going through a host buffer, which needs a native copy in `wprcpu`.
  Its leaderboard rows arrive but are not drawn.
- **WP8 titles that now start but stop early**: Doodle God Blitz (16 frames), Hexic, Asphalt
  Overdrive and Bubble Guriko (no frames), Fruit Ninja 2013 and Jetpack Joyride (a few frames).
  Unity WP8 games run their managed shell and draw black (the Unity engine is not hosted). WP8
  Microsoft Minesweeper draws nothing.
- **Big Buck Hunter Pro** hangs on LOADING when a hunt starts: its loader spin-waits on a field the
  JIT hoists out of the loop.
- **Modern Combat 4** is not paused by calls or the lock screen (`Obscured` is never raised), and its
  Min leaderboard rule is unverified because it never posted a score.
- **WP8 movies on Android** need sidecars, so a WP8 game installed before this release needs a
  re-patch; the automatic repatch at launch does not transcode.
- **Guide message boxes on Android** may not answer when closed with Back.
- **Galactic Reign** overflows its own stack in about 2 of 9 launches, on either driver.
- **Windows forced Vulkan/OpenGL** lack fixes that only the Android graphics library carries
  (`FNA3D.dll` can't be rebuilt here). Windows uses Direct3D 11 unless you force something else.
- **Not tested on a Mali phone**, and most of this release was tested on Windows and the Android
  emulator rather than on a Galaxy S24.

> **Upgrading is normal.** Install the new APK over the top on Android, or run the installer on
> Windows. Your games, saves and sign-in stay put. Installed games are updated automatically the
> first time you start them. Two exceptions: **to get movies on Android**, re-patch any game with
> cutscenes installed before this release (long-press it → re-patch), Halo included. And
> **reinstall** the WP8 Microsoft Minesweeper and What In The World? from their XAPs, plus any game
> whose name shows as "@AppResLib.dll,-100".
