# WPR 0.2.08: full release notes

The long version: what each change is, how it was tested, and what's still missing. The short
summary that goes on the release page is [`0.2.08.md`](0.2.08.md) beside this file. 0.2.07 was the
Windows uninstall fix alone, so everything here is new since 0.2.06.

---

## The rule this release follows: a game's own libraries run as shipped

Many games bring their own libraries: SharpDX, the Windows Phone Toolkit, ad and analytics SDKs,
engine frameworks. Older WPR builds sometimes redirected those to WPR's own imitations, and whatever
the imitation left out quietly stopped working. This release reverses that wherever it could. The
game's own code runs, and WPR supplies the phone features underneath it. Two stand-ins remain, for
native ARM components inside managed games (`Microsoft.Xbox` and `SharpDX.WP8`), until WPR can host
that ARM code from a managed game. The rule is written up in `.claude/rules/never-shim-bundled-dlls.md`.

## Windows Phone 8 games

### Gravity Guy 2 runs its own SharpDX (patcher v46)

SharpDX's only way into native code is the `SharpDX.WP8` component each such game ships, which hands
SharpDX the addresses of system functions (`D3D11CreateDevice`, `CreateFile2`, `XAudio2Create`, ...).
WPR answers those with its own host Direct3D 11 and DXGI objects (`WPR.Engine.HostDirect3D`), and the
game's own SharpDX and SharpDX Toolkit run unmodified. Frames are recorded and replayed through the
same GPU path the native WP8 runtime uses, so it draws on D3D11, Vulkan and OpenGL alike. On the way:
`Package.Current`, `DisplayProperties` and the static `SystemTray` members; `Touch.FrameReported`;
marketplace reads answer an empty marketplace instead of failing.

Verified: menus, PLAY, the first level with its tutorial, on desktop D3D11, Vulkan and GLES 3.0.
Not run on a phone. Music isn't played yet (its songs are MP3).

### Microsoft Mahjong, Minesweeper and Solitaire (patcher v47–v49, v51)

Arkadium's three games run their own SharpDX engine behind a Silverlight page. They needed:
- a background grid that connects at once and keeps its device;
- `CompositionTarget.Rendering` raised every frame (their engine is ticked only from it);
- the WP8 scale factor (160);
- touch turned into the phone's portrait frame;
- queued `Dispatcher.BeginInvoke`;
- data binding converters and fallbacks, and `RichTextBox` with its document types;
- `Clip`, skew and repeating storyboards, and reused GPU buffers. Memory at 1,200 frames fell from about 1 GB to about 130 MB.

Verified on desktop D3D11: Mahjong matches its tutorial pair, Minesweeper opens tiles, Solitaire deals
Klondike.

### Managed WP8 games reach Xbox Live (patcher v43–v45)

About 40 managed WP8 games call `Microsoft.Xbox` from C#. They now go through the same door as native
games: sign-in as your WPR Hub player, achievements into WPR's store and the hub, leaderboards on the
hub. WinRT async operations are real objects over .NET tasks. WinRT metadata's `mscorlib 255`
references are retargeted. A package's own XNA-shaped layer (Gravity Guy 2's) is no longer replaced
by WPR's.

### "Guest thread exited and no thread is runnable"

This was the top WP8 crash group (Fruit Ninja 2013, Jetpack Joyride, Halo, all on Android). It had two
causes:
- **A thread that ended while others were in a short timed wait was taken as a deadlock.** FMOD waits 2 ms at a time. WPR now waits out the earliest timed wait instead.
- **Mandreel games (Fruit Ninja 2013, Jetpack Joyride) need a message thread their managed page starts.** WPR now runs one for them.

Fruit Ninja 2013 and Jetpack Joyride reach their menus on all four desktop drivers. Halo still plays a
mission. The Mandreel thread is a stand-in for the game's own page code and is noted as such.

### Smaller WP8 changes

- **Inferred pages** use only the start page, and follow a `DispatcherTimer`'s Tick.
- **Leaderboards:** WP8 games send their boards' real names to the hub (see WPR Hub below).

## Windows Phone 7 and Silverlight games

### AE Fruit Slash (patcher v56–v58)

- **Saves and Back navigation:** saves, its ads SDK start-up and Back navigation work. A WP7 library can ask what its own package is called (`Module.Name`, `Assembly.Load` by display name).
- **Touch ids:** every new touch gets a new id, as Windows Phone did.
- **Named mutexes on Android:** these failed at launch, because the runtime wanted to write to `/data/local/tmp`. They now fall back to a process-local mutex.
- **The crash on phones:** after a lot of slashing the game crashed on phones. Effects the game never disposed are now collected, and FNA3D's Vulkan driver no longer aborts the process when a descriptor pool fills.

Verified on all four desktop drivers, both emulator drivers, and the Galaxy S24 on Vulkan (over
4,000 effects in one session, no crash).

### iRunner (patcher v59)

- **Store:** its bundled store API is answered.
- **Settings:** isolated-storage settings can hold the game's own classes.
- **Game-thread context:** the game thread has a synchronisation context.

Verified from menus through a full run on every GPU path reached. The copy in our library was
PlayReady-encrypted; a decrypted copy was used.

### PointAbout Mashup apps: Fox News and YouTube (patcher v52–v54)

- **Fox News:**
  - `ResourceDictionary.MergedDictionaries` has Silverlight's type;
  - `sys:String` / `sys:Double` resources load;
  - items panels and container styles work;
  - `ListBox` has Silverlight's default visual tree (a ScrollViewer, an ItemsPresenter and a VirtualizingStackPanel), which Fox News's bundled `LazyListBox` needs;
  - the toolkit's Pivot gets its template.
- **YouTube (WP8):** `MediaLibraryExtensions`, `ApplicationProfile`, `VoiceCommandService`, `ThreadPool` and navigation events.
- **The Silverlight host's thread** has a `DispatcherSynchronizationContext`, so `await` and `BackgroundWorker` come back to it.

Fox News shows its feed's layout; much of the content stays empty, which is still open.

### The Windows Phone Toolkit's gestures (patcher v50)

The old redirect of the toolkit's gesture types pointed them nowhere. No `Tap="…"` handler in XAML ever
bound, which is why Microsoft Minesweeper's and Sudoku's menus ignored taps. The toolkit now runs its
own gesture code. WPR supplies what it calls:
- `Touch.FrameReported` with Silverlight's Down/Move/Up values;
- `VisualTreeHelper.FindElementsInHostCoordinates`;
- `TransformToVisual` as a real `MatrixTransform`;
- `DispatcherTimer` ticking on the game thread, with a race in `Stop` fixed.

`ApplicationBar` exists (stored, not yet drawn), so pages that declare one open.

Verified: Minesweeper's and Sudoku's menus, Back, Sudoku's training board. A/B over 12 titles showed
no regressions. Hold, drag and pinch in play are not yet tested.

### Other fixes

- **SPY Mouse:** a missing folder now gives `FileNotFoundException`, as on WP7, not
  `DirectoryNotFoundException`. SPY Mouse catches only the first, and Play used to give an empty
  screen.
- **Zuma's Revenge:** content-reader type names reach an assembly the installer renamed. This was only a
  noisy report; the game was never affected.
- **Contract Killer:** a signed-in gamer gets a token-shaped partner token instead of an empty string,
  so Glu's Xbox login no longer throws and ends the run.
- **Guide message boxes on Windows** ("quit?", "screen lock settings?", "rate us"). These used the
  MessageBox.Avalonia package, which can't load against the Avalonia this app uses. They now use the
  same built-in window as Silverlight's `MessageBox`, and every way of closing one answers. The
  package is removed from both heads.

## WPR Hub

- **Leaderboard names.**
  - WP8 games send the board's name from their own Xbox config, or WPR's table for Seasons, Star Wars and Star Wars II.
  - Other new boards get a readable name made from the key ("Best score", "Best score (board 2)").
  - A hub migration renames boards still called by their raw key.
  - A name set by an admin or the definitions repo is never overwritten.
- **Installs fill in a game's details.** After an install WPR offers the hub the game's name,
  publisher, developer, platform and icon. The hub fills only what it doesn't have yet. Queued and sent
  later, like crash reports, and never in the way of the install.
- **Game invites and notifications.** Invite a friend to a game from a conversation.
  On Android, push notifications (Firebase) for messages, invites and friend requests, and an
  in-game toast for achievements. Each kind can be switched off in settings.
- **Retired online services.** A game's web requests to a service WPR Hub has taken over are sent to
  the hub, with your service token when signed in. Pool Pro Online 3's lobby is the first. Socket
  calls keep Silverlight's "always completes asynchronously" behaviour (patcher v55–v56).
- **Fewer false crash reports.** A run's problem file is now locked while the run is alive, so a
  launcher that restarts mid-game can't report it. On Android, a game the system closed on purpose
  (`ApplicationExitInfo`: an app install, a user stop, low memory) is no longer filed as a native
  crash.

## Android

- **The on-screen keyboard** no longer covers text boxes. Under edge-to-edge the window isn't resized
  for it, so pages now pad for whichever is taller, the keyboard or the navigation bar. The reply box
  in WPR Hub conversations was the visible case.
- **FNA3D's Vulkan driver keeps its swapchain** when a present reports "suboptimal" only because of the
  deliberate identity transform. The emulator froze on that, and phones rebuilt the swapchain every
  frame. `libFNA3D.so` is rebuilt for all three ABIs.

## Known issues

- **Fox News:** the layout shows, but most content is empty.
- **Jetpack Joyride:** world art draws only on OpenGL.
- **Mandreel titles on a wide desktop window:** they draw in a strip at the left.
- **Halo:** some objects are still drawn as black shapes.
- **Application bars** aren't drawn.
- **The two stand-ins:** `Microsoft.Xbox` and `SharpDX.WP8` stand in for those games' bundled components, until WPR can host their native ARM code from a managed game.
- **Testing:** mostly on Windows and the Android emulator. Phone testing was a Galaxy S24 only; nothing was run on a Mali device.

## Upgrading

Install over the top. Games repatch themselves on their first launch: the patcher went from v42 in
0.2.06 to v59.
