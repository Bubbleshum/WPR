### Windows Phone 8 Unity games

Most Windows Phone 8 games built with Unity keep their game logic in .NET code that the phone ran
itself, so until now WPR could show their splash screen and nothing more. WPR now runs a real .NET
runtime inside the emulated phone, built for the phone's 32-bit ARM processor, and hands it the
game's own files, untouched. Getting it to run meant teaching the emulated phone much more of
Windows:

- **Errors handled the way Windows does it.** .NET depends on the processor stopping on a bad
  memory read (that is how it notices a missing object), and on Windows walking back through the
  code to find who handles the error. Both now work exactly enough for .NET and for the game's own
  C++ code, which throws and catches errors through the same machinery.
- **The rest of the system .NET expects**: thread pools and timers, a way to wait on many file and
  network operations at once, cryptographic hashing, the system's folders, network settings, and
  dozens of smaller calls.
- **The bridge between the game's .NET page and its Unity engine**, in both directions, so the page
  and the engine can call each other as they did on the phone.
- **What these games use on the phone**: saved settings, sharing, opening web pages, sending a text,
  saving pictures, the microphone, sound, and live tiles.

**Temple Run, Temple Run 2 and Temple Run: Oz** (both versions) are the first to play: the menus,
runs with turning, jumping and sliding, coins, the results screen, saving your progress, and Back
to leave. Tested on Windows and a Galaxy S24. Other Windows Phone 8 Unity games should get much
further than before too, but only these have been tested properly.

On a phone these games take about 25 seconds to start (a little longer the first time after an
update), as WPR is starting a whole .NET runtime for them. The game's splash screen shows meanwhile.

### Every Windows Phone 8 game

- **A splash screen**: each game shows its own launch picture while it loads, as the phone did,
  instead of a black screen.
- **Steady memory**: games create and throw away small system objects (timers, signals, values)
  many times a second, and WPR never threw them away. On Temple Run: Oz's menu WPR's memory went
  from 130 to 360 MB in five minutes; it now stays flat around 110-130 MB.
- **Faster**: the emulated processor skips work it was repeating needlessly, and the most common
  system calls (comparing text, taking and releasing locks) now run inside the game's own code
  instead of stopping to ask WPR.
- **Sound keeps time while a game is busy loading or shutting down**, so a game that waits for its
  sound engine to finish no longer freezes on its last frame.
- **Graphics**: one kind of texture lookup in older-style shaders no longer fails to compile, so the
  scenery it drew is no longer missing.
- **Games installed with an older WPR** that were really Windows Phone 8 games are recognised as such
  when you start them, with no reinstall.

> **Upgrading.** Install the new APK over the top on Android, or run the installer on Windows. Your
> games, saves and sign-in stay put. Nothing needs reinstalling.
