> **Switched to OpenGL to get around a crash?** If you changed settings → graphics to OpenGL because
> games crashed on Vulkan, switch it back to Vulkan after updating. Your own choice always wins over
> WPR's, so the Vulkan fix only reaches you once you put it back.

### Windows games that couldn't find Microsoft.Phone

The Windows installer was shipping WPR's stand-in for the phone's own libraries with the wrong
version number on it. Games ask for a particular version of those libraries, and since the one in
the installer looked older than the one they wanted, they couldn't load it and stopped at once.
This was a mistake in how the Windows release was built, not in the games, and it could hit any
Windows Phone 7 or 8 game that uses the phone's libraries. Android was never affected.

### Mali phones and Vulkan

WPR asked every phone's Vulkan driver for three optional extras, without checking first. Some Mali
graphics chips don't have one of them (drawing in wireframe), so the driver refused to start and
every game closed straight away. WPR now only asks for what the phone has.

WPR then switched to OpenGL by itself, as it should, but forgot again after one launch, so every
second launch crashed. It now remembers until you pick a driver in settings or update WPR.

### Black screens on OpenGL

Two separate problems, both fixed:

- **Games that load in the background.** Bejeweled Live+ loads its pictures in the background while
  the game waits for them, and OpenGL could only take a picture from the background once the next
  frame was drawn, which never came. Background loading now gets its own OpenGL connection to the
  graphics chip, so it no longer waits for a frame. That helps any game that loads this way.
- **Drivers that claim more than they have.** Some OpenGL drivers answer "yes" when asked for a
  drawing function they don't actually have. WPR believed them, so on chips that only support
  OpenGL ES 3.1, a common kind of drawing in Archer, The Treasures of Montezuma and others did
  nothing at all. WPR now checks the chip's OpenGL version first, and draws another way when the
  function isn't there.

### AE 3D Motor and Skulls of the Shogun

- **AE 3D Motor** read the "app resumed" signal WPR sends at every start as a real resume, cleared
  its screens and stopped on a white screen. Behind that, its splash screen loaded its pictures before
  the game's graphics were fully set up, which crashed. Both are fixed; it plays on Windows and on the
  Android emulator.
- **Skulls of the Shogun** closed while loading its world map, because WPR misread a type name stored
  in the map file. WPR now leaves reading type names to .NET itself.

### Known issues

- **Galactic Reign** sometimes closes while loading on Android. It's unrelated to graphics, and a
  fix is being worked on separately.

> **Upgrading is normal.** Install the new APK over the top on Android, or run the installer on
> Windows. Your games, saves and sign-in stay put. Nothing needs repatching or reinstalling.
