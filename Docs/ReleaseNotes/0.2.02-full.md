# WPR 0.2.02: full release notes

The long version: what each change actually is, how it behaves, and what's still missing. The
short summary that goes on the release page is [`0.2.02.md`](0.2.02.md) beside this file.

---

**Leaderboards show real scores, Asphalt 5 races on Android again, and Fruit Ninja and Doodle God
stop tripping over their own menus.**

0.2.00 brought WPR Hub and online leaderboards. This release is the follow-up from people actually
using them: scores that read as 0, a gamerpic that took over Fruit Ninja's home screen, and a
gamerpic button that froze the menu. Alongside those, two game fixes that had been waiting: Asphalt
5's loading screen on Android, and Doodle God's crash when you change your mind about quitting.

### Leaderboards read as 0

**The symptom:** a game's leaderboard opened, listed the right players in the right order, and
showed 0 against every one of them. On the WPR Hub website the same board had real scores.

**Why it happened:** an Xbox LIVE leaderboard entry has two ways to hold a score. There's the
*rating*, which is what the board is sorted by, and there are *columns*, extra named values a game
can store alongside it. The standard boards every Windows Phone game used (best score and best
time, lifetime or recent) always had one column filled in for you: **BestScore** on a score board,
**BestTime** on a time board, both holding the rating.

Games relied on that. Almost all of them post a score by setting the rating, and then read it back
from the column. We checked the 34 installed games that read leaderboards: Zuma's Revenge, Cut the
Rope, Doodle Jump, Fragger, G-Switch, iStunt 2, Monsters, Kinectimals, Sonic 4 and many more read
`BestScore`; Mirror's Edge and Dream Track Nation read `BestTime`. Those two names are the only
ones in use.

WPR Hub stores the rating, plus any columns the game set itself. A game that only set the rating
had no columns, so when it looked up `BestScore` it found nothing, and nothing reads as 0.

**The fix:** when WPR hands a game a leaderboard entry, it now fills in the board's standard
column from the rating, exactly as Xbox LIVE did: `BestScore` for a score board, `BestTime` for a
time board. If the game wrote that column itself, its own value is kept.

Nothing changes on the hub, and nothing needs re-posting: the scores were right all along, and
every board shows them correctly the next time a game opens it.

**One safety change came with it.** A column read back as a whole number can now hold a score
too large for the 32-bit number most games ask for. Rather than letting that crash the game's
leaderboard screen, WPR caps it at the largest value the game can hold.

### Gamerpics were too big

**The symptom:** on Fruit Ninja's home screen, your gamerpic sat in the top corner at four times
the size it should have been.

**Why it happened:** every gamer picture a Windows Phone game ever received was 64×64 pixels, and
games were written knowing that. Fruit Ninja turns your picture into a button and sizes the button
from the picture itself, so whatever size it's given is the size it draws. WPR was handing it the
hub's 256×256 version.

**The fix:** whatever a game asks for, it now gets a 64×64 picture, scaled down from your hub
gamerpic (or from the built-in default when you're signed out). It's done when the game asks, not
when the picture is downloaded, so the copy already saved on your device is fine as it is.

### Everyone else's gamerpic on a leaderboard

Some games draw a little picture beside every name on a leaderboard. Zuma's Revenge does, for
example. They do it by asking each player's profile for its picture, and every one of those
answered with **your** picture, because that was the only one WPR had.

Leaderboard rows now carry each player's own gamerpic from the hub. WPR fetches the small 64-pixel
version, keeps it for the rest of the session so paging back and forth doesn't fetch it again, and
only ever fetches it from the hub itself. A player with no gamerpic, or one that can't be fetched
in a few seconds, gets the built-in default picture rather than yours.

**Some games only ever draw yours.** Fruit Ninja is one: it loads your picture once when you sign
in and draws it beside your own row, and other rows are a name and a score. That's how it was
made, and on a real Windows Phone it looked the same.

### Fruit Ninja froze after tapping your gamerpic

**The symptom:** tap your gamerpic on Fruit Ninja's main menu, and the game shows an error box.
Close it, and the menu ignores every touch from then on.

**Why it happened:** the gamerpic button asks the phone to open your Xbox LIVE **gamer card**, a
system screen that sat over the game until you pressed Back. WPR doesn't have that screen, and its
stand-in reported an error instead. Fruit Ninja caught the error and showed its own message, but
by then its menu was halfway through handling your tap and never finished, so it stopped listening.

**The fix:** WPR now behaves as though the screen opened and you came straight back. The game
carries on as normal. The same applies to every Xbox LIVE screen a game can ask for, any of which
would have done the same thing: the gamer card, friends, friend requests, messages, composing a
message, game invites, party, players, player review and the marketplace.

### Asphalt 5 on Android

**The symptom:** the garage showed the car with a streaky pink and white body, and starting a race
left you on a loading screen that never finished. On the OpenGL graphics driver, that loading
screen was upside down.

**Why it happened:** most Windows Phone games ship their textures in a compressed format (DXT)
that desktop graphics cards understand and phone graphics chips don't. So on Android, WPR unpacks
those textures into plain colour when a game loads them. Until now, the unpacked texture then told
the game it was a plain colour texture and always had been.

Most games never ask what format a texture is. Asphalt 5 does: it uses the answer to tell car
bodies, which it can repaint in your chosen colour, from everything else. Every body is a plain
colour texture, but the wheel and interior sheets are compressed. Told that the wheel sheet was
plain colour too, Asphalt took it for a body and tried to repaint it without the information a
body comes with, and that failed on every frame. The repaint failing is the streaky car; the same
failure on every frame of the loading screen is why the race never loaded.

**The upside-down loading screen was the same failure.** Asphalt draws each loading step into an
off-screen image and then switches back to the screen. The failure struck in between, so the
switch back never happened. The OpenGL driver flips anything drawn into an off-screen image, and
with the switch missed, that flip carried on to the screen itself.

**The fix:** a texture now reports the format the game shipped it in, and WPR unpacks it quietly
underneath, so Asphalt takes exactly the path it took on a real phone. Races load and play on both
the Vulkan and OpenGL drivers.

Two related changes:

- **Compressed textures on 3D environment maps** (cube maps, used for reflections) are now
  unpacked on Android too. Before, they weren't handled at all.
- **A game can't read back the pixels of a compressed texture** once WPR has unpacked it, because
  there's no way to re-compress them. WPR hands back an empty image and notes it in the log. A
  real Windows Phone refused that request outright, so no game depends on it.

**Why this was marked as working on Android:** the Android emulator we test on has a graphics
driver that *does* understand DXT, so textures were never unpacked there and the bug never
appeared. Phone-only texture problems now get tested with the unpacking forced on.

### Doodle God, and resuming games

**The symptom:** press Back on Doodle God's main menu, answer **NO** to "quit?", and the game
crashes.

**Why it happened:** a Windows Phone app is told two different things at two different times. When
it starts, it gets **Launching**. When you come back to it after leaving, it gets **Activated**.
WPR got that right at start-up, but every time a game got the focus back afterwards, it said
*Launching* again, as if the game had just been started.

Plenty of things take a game's focus and give it back: switching to another app and returning,
and on Android, any message box the game shows itself. Most games don't
mind being told they've launched twice. Doodle God reloads all its data when it hears it, and its
data can only be loaded once. So answering NO to its own question closed the box, the game got the
focus back, heard *Launching*, reloaded, and crashed.

**The fix:** only the first time is a launch. Every time after that, a game is told it was
**Activated**, as a Windows Phone would. Doodle God now carries on from its menu.

This applies to every game, on both Android and Windows.

### WPR Hub sign-in

**The symptom:** signing in on Android sends you to your browser to approve the link key. Coming
back to WPR afterwards could show "Software caused connection abort" and abandon the sign-in.

**Why it happened:** while you're in the browser, WPR keeps asking the hub whether you've approved
yet. Android cuts off the network connections of apps sitting in the background, so the first
question after you came back could go out on a connection that no longer existed. That one failed
question ended the whole sign-in.

**The fix:** a question that fails is now simply asked again, on a fresh connection, until you
approve or the key expires. Asking again is safe: the hub only uses up the key when it hands over
your sign-in.

### What's still missing

- **There's no Xbox LIVE gamer card, friends list or marketplace inside games.** Games that offer
  them now carry on instead of breaking, but the screens themselves don't appear. Your friends and
  profile are on the WPR Hub tile (Android) and HUB tab (Windows).
- **Friends leaderboards show only your WPR Hub friends**, as Xbox LIVE showed only your Xbox LIVE
  friends. In a game whose only leaderboard is a friends board, such as Angry Birds, you'll see
  just yourself until you add friends on the hub.
- **A game that reads back the pixels of a compressed texture on Android gets an empty image.**
  We haven't found a game that needs them.
